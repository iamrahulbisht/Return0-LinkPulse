# Deploy LinkPulse

| Part | Where | How |
|---|---|---|
| Web app (React SPA) | **Vercel** | `apps/web`, static build, `/api/*` rewritten to Render |
| API + redirects + click worker | **Render** | Docker image from `apps/api/Dockerfile` (Blueprint: `render.yaml`) |
| Database | **Neon** Postgres | pooled URL for the app, direct URL for migrations |
| Cache + queue + live pub/sub | Hosted **Redis** (Upstash or Redis Cloud) | one `REDIS_URL` |

```
phone ──GET /<code>──────────────────────────► Render (Docker: Express API)
browser ─► Vercel (SPA) ──/api/* rewrite──────► Render ──► Neon Postgres
browser ──EventSource /stream?token=──────────► Render ──► Redis (cache, BullMQ, pub/sub)
```

Pick regions close to India and close to each other: **Render Singapore**, **Neon AWS ap-southeast-1 (Singapore)**,
**Redis in ap-southeast-1 / Singapore** (or Mumbai if your provider has it). Cross-region hops add latency to every redirect.

Free tiers change. Check the current limits on each site before the demo.

---

## 0. Put the code on GitHub

Render and Vercel deploy from a Git repository. Create a private repo and push this folder (`.gitignore` already
keeps `.env` files and `node_modules` out). Never commit `apps/api/.env`.

## 1. Neon (Postgres)

1. Create a project → region **AWS Asia Pacific (Singapore)**, Postgres 16.
2. Dashboard → **Connect**. Copy two strings:
   - **Pooled** (host contains `-pooler`) → this is `DATABASE_URL`. Append `&pgbouncer=true&connect_timeout=15`
     (the string already has `?sslmode=require`).
   - **Direct** (toggle "Connection pooling" off) → this is `DIRECT_URL`. Prisma migrations need it; PgBouncer breaks them.

```
DATABASE_URL=postgresql://<user>:<password>@ep-xxxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&pgbouncer=true&connect_timeout=15
DIRECT_URL=postgresql://<user>:<password>@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```
You do not run migrations by hand: the container runs `prisma migrate deploy` (non-destructive) every time it starts.

## 2. Redis

Either works; the app only needs `REDIS_URL`.

- **Upstash**: create a Redis database (region ap-southeast-1). Use the `rediss://` URL (TLS):
  `rediss://default:<password>@<name>.upstash.io:6379`. Every command counts toward the free quota; the click worker
  is already tuned to poll slowly when idle (`drainDelay` 30 s), but watch the usage page during the event.
- **Redis Cloud** (redis.io): create a free database, copy the public endpoint:
  `redis://default:<password>@redis-12345.c1.ap-southeast-1-1.ec2.cloud.redislabs.com:12345`.
  Set the **eviction policy to `noeviction`** (database → Configuration). BullMQ needs it; with an evicting policy queued
  clicks could be dropped and BullMQ logs a warning.

If Redis is down or missing, LinkPulse still works (links from Postgres, clicks written straight to Postgres) — slower, no click lost.
`/health` shows `"redis":"up" | "down" | "off"`.

## 3. Render (API, Docker)

1. Render → **New → Blueprint** → connect the GitHub repo. It reads `render.yaml`: one Docker web service
   `linkpulse-api`, plan free, region Singapore, health check `/health`.
2. Fill the secrets it asks for:

| Key | Value |
|---|---|
| `DATABASE_URL` | Neon pooled string (step 1) |
| `DIRECT_URL` | Neon direct string (step 1) |
| `REDIS_URL` | from step 2 |
| `SHORT_BASE_URL` | `https://linkpulse-api.onrender.com` — the service's own URL (Render shows it; it may have a suffix if the name is taken) |
| `WEB_ORIGIN` | `https://<your-project>.vercel.app` (fill in after step 4; comma-separate extra preview URLs) |

`JWT_SECRET` and `HASH_SALT` are generated by Render. `NODE_ENV=production`, `RUN_WORKER=true`, `TRUST_PROXY_HOPS=1`,
`GEOIP_ENABLED=true` come from the Blueprint. The API refuses to start in production if `SHORT_BASE_URL`/`WEB_ORIGIN`
still say `localhost` (check the Render logs for "Invalid environment").

3. Deploy. Logs should end with `All migrations have been successfully applied` and
   `[api] listening on :10000 · short links at https://… · worker on`. Open `https://<api>/health`.

Notes
- The free instance **sleeps after ~15 minutes idle**; the first request then takes up to a minute. Open `/health` 10 minutes before judging.
- The click worker runs inside the API (`RUN_WORKER=true`) because background workers are not on the free plan. To split it later, add a
  Render background worker with the same image and the command `node dist/queue/workerMain.js`, and set `RUN_WORKER=false` on the web service.
- Memory: measured **≈ 182 MiB** in the container with the offline city database loaded (local test, 18 Oct). Free instances have 512 MB.
  If Render reports out-of-memory, set `GEOIP_ENABLED=false` (cities then show as "—").

## 4. Vercel (web app)

1. Edit [`apps/web/vercel.json`](../apps/web/vercel.json): set the `/api/:path*` rewrite destination to **your** Render URL
   (Vercel rewrites cannot read environment variables). Commit and push.
2. Vercel → **Add New → Project** → import the repo.
   - **Root Directory: `apps/web`** (everything else comes from `vercel.json`: framework Vite, install `cd ../.. && npm ci -w apps/web`,
     build `npm run build`, output `dist`, SPA fallback to `index.html`).
   - Environment variable: `VITE_SHORT_BASE_URL = https://linkpulse-api.onrender.com` (your Render URL). Leave `VITE_API_BASE` unset (`/api`).
3. Deploy, copy the production URL, put it in Render's `WEB_ORIGIN`, and redeploy the Render service.

Why the rewrite: the browser only ever talks to the Vercel domain for `/api`, so the `lp_session` cookie is first-party
(`Secure; HttpOnly; SameSite=Lax`) and there is no cross-site cookie problem. Short links and the live stream go straight to Render.

## 5. Seed the demo data (once, on purpose)

The seed **wipes every table** and writes the sample data (users `admin@ / team@ / other@linkpulse.test`, ~2,000 clicks).
It refuses to run in production unless you set `SEED_ALLOW_RESET=true`. Run it from your laptop against Neon's **direct** URL:

PowerShell:
```powershell
$env:NODE_ENV="production"; $env:SEED_ALLOW_RESET="true"; $env:DATABASE_URL="<Neon DIRECT url>"; $env:DIRECT_URL="<Neon DIRECT url>"; $env:REDIS_URL="<REDIS_URL>"; $env:SEED_PASSWORD="<a strong demo password>"; npm run db:seed -w apps/api
```
Git Bash / macOS / Linux:
```bash
NODE_ENV=production SEED_ALLOW_RESET=true DATABASE_URL='<Neon DIRECT url>' DIRECT_URL='<Neon DIRECT url>' REDIS_URL='<REDIS_URL>' SEED_PASSWORD='<a strong demo password>' npm run db:seed -w apps/api
```
Passing `REDIS_URL` lets the seed clear cached links (new ids). Re-seed within the hour before judging (the seeded traffic spike is "in the last hour").
Close the terminal afterwards so the URLs and password are not left in your shell history; on PowerShell also run `Remove-Item Env:DATABASE_URL, Env:DIRECT_URL, Env:REDIS_URL, Env:SEED_PASSWORD`.

- [ ] `https://<api>/health` → `{"ok":true,"redis":"up"}`
- [ ] Vercel URL → sign in as `team@linkpulse.test`; refresh `/links/…` directly (SPA fallback works)
- [ ] Create a link → open it on a phone (mobile data) → it shows on the dashboard within seconds (“Live · updated …”)
- [ ] Scan the Main QR → link details shows “QR · Main QR”
- [ ] Share a link in WhatsApp → “Bots filtered” goes up
- [ ] Admin (`admin@linkpulse.test`) → disable a link → phone shows “This link has been turned off” → Restore (with a reason)

## Troubleshooting
| Symptom | Likely cause |
|---|---|
| Web app shows "Could not reach LinkPulse" / 404 on `/api/...` | `vercel.json` rewrite still points to the wrong Render URL |
| Signed in, but every page says "Please sign in" | Calling the Render URL directly instead of `/api` on Vercel (cookie is set on the Vercel domain) |
| Dashboard says "Updating every 10 s" instead of "Live" | Render `WEB_ORIGIN` does not include the exact Vercel origin (no trailing slash), so the stream is blocked by CORS |
| Render log: `Invalid environment` | A variable is missing or still `localhost` |
| Render log: `P1001` / timeout to Neon | Wrong URL or missing `sslmode=require`; Neon compute was suspended (first request wakes it) |
| Migrations hang or fail with "prepared statement" errors | `DIRECT_URL` is the pooled URL; use the direct one |
| BullMQ warning about eviction policy | Set Redis eviction policy to `noeviction` |
| Instance restarts with out-of-memory | Set `GEOIP_ENABLED=false` |
| Short links / QR codes show `localhost` | `SHORT_BASE_URL` (Render) or `VITE_SHORT_BASE_URL` (Vercel, needs a redeploy) not set |

## Run the production image locally
```bash
docker build -f apps/api/Dockerfile -t linkpulse-api .
```
```bash
docker run --rm -p 4100:10000 --env-file apps/api/.env -e PORT=10000 linkpulse-api
```
(With the local `.env`, change `localhost` in `DATABASE_URL`/`DIRECT_URL`/`REDIS_URL` to `host.docker.internal`, and keep `NODE_ENV=development`
— production mode refuses `localhost` URLs on purpose.)
